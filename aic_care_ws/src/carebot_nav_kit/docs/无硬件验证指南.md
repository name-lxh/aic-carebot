# 无硬件验证指南（虚拟机）

> 适用：Ubuntu 18.04 + ROS Melodic 虚拟机，没有比赛硬件。
> 目的：在不排队等实车的情况下，把导航代码验证到"上实车就能跑"的程度。

---

## 为什么需要这个

比赛用车在实验室排队，一次只能用一小会儿。如果每次都把
"编译有没有过 / 参数对不对 / 规划器能不能工作" 带到实车上试，
排队时间全浪费在低级错误上。

本指南的做法是：**在虚拟机里把整条导航闭环真的跑起来**，
只把"真实传感器"换成仿真数据。下游的 costmap、amcl、move_base
全部是真实节点、真实配置。

```
实车：  激光雷达 ─┐
        IMU     ─┼─→ laser_filter → costmap → amcl → move_base → /cmd_vel → 底盘
        底盘里程计─┘

虚拟机：假传感器 ─┘   （同一条下游链路，同一份配置）
```

## 六项验证各查什么

| # | 项目 | 查什么 | 耗时 |
|---|---|---|---|
| 1 | 脚本可执行位 | `rosrun` 的前提。打包/传输常丢 `+x`，导致所有节点起不来 | 秒 |
| 2 | catkin 编译 | 语法、依赖、包结构 | 1~2 分 |
| 3 | launch 解析 | `$(find ...)` 引用完整性、参数名对不对 | 秒 |
| 4 | 纯逻辑单元测试 | 二维码解析、房间顺序、设备映射、配置一致性（58 用例） | 秒 |
| 5 | 配置一致性校验 | 22 项跨文件检查（半径/坐标系/速度上限/EKF 维度…） | 秒 |
| 6 | **端到端导航** | **真的走到目标点** | 1~2 分 |

**第 6 项是核心。** 前五项都过了也不能说明规划器能工作 ——
只有让 move_base 真的算出路、真的发出 `/cmd_vel`、机器人真的到达，
才算验证过。

## 仿真器怎么用

### 假传感器

`nodes/fake_sensors.py` 模拟出导航栈需要的全部输入：

| 话题 | 内容 |
|---|---|
| `/odom` | 里程计（可加噪声与漂移） |
| `/scan` | 激光（从内存地图做射线投射，参数对齐 RPLIDAR A1M8） |
| `/imu/data` | IMU |
| `/tf` | `odom → base_footprint` 及各传感器静态变换 |
| `/sim/ground_truth` | **真值**，测试脚本用它判定是否真的到达 |

关键设计：它**订阅 `/cmd_vel` 并按指令积分位姿**，所以 move_base
发出的速度会真的"驱动"机器人，形成闭环。

```bash
# 默认：8.4×8.0 m 房间，中间有障碍
rosrun carebot_nav_kit fake_sensors.py

# 指定起始位姿
rosrun carebot_nav_kit fake_sensors.py _start_x:=1.0 _start_y:=-1.0

# 关噪声（调规划器时更干净）
rosrun carebot_nav_kit fake_sensors.py _noise:=0.0

# 模拟里程计漂移 5%（测 EKF 纠偏能力）
rosrun carebot_nav_kit fake_sensors.py _odom_drift:=0.05
```

### 仿真地图

```bash
python3 scripts/make_sim_map.py          # 生成 maps/sim_map.{pgm,yaml}
```

生成的地图与 `fake_sensors.py` 的世界**逐字符一致**
（`test_pure_logic.py` 会校验，防止改了一个忘另一个）。

> ⚠️ 这是**测试用地图**，不是比赛场地地图。
> 比赛场地地图要在现场用 gmapping 建，见 `docs/建图与导航操作手册.md`。

## 能验证什么 / 不能验证什么

### ✅ 能验证

- 代码能否编译、launch 引用是否完整
- costmap 能否正确吃到激光障碍
- amcl 能否在给定地图上定位收敛
- move_base 全局/局部规划能否算出路
- 速度上限是否满足赛题规则（≥0.6 m/s、≥4 rad/s）
- DWA 参数是否合理（多久到达、误差多大）
- 任务状态机的状态流转（不接实物，用 `dry_run`）

### ❌ 不能验证

- **真实底盘的运动学**：轮距、减速比、转向半径要靠
  `calibrate_linear.py` / `calibrate_angular.py` 在实车上标定
- **真实传感器噪声特性**：仿真噪声是高斯白噪声，真实的更复杂
- **串口协议**：STM32 的 `0x5A|LEN|ID|CMD|...` 协议要在实车上测
- **物联网真实设备**：HomeAssistant 的实体要在现场确认
- **语音/人脸/二维码**：需要真实麦克风与摄像头

```bash
bash scripts/verify_all.sh --quick
```

## 踩过的坑（改代码前请先看）

这台环境上有几个**只在目标版本才暴露**的问题，本地开发时测不出来。
每一个都留了回归测试，改代码前建议先跑一遍单元测试。

### 1. Python 3.6 没有 `TextIOWrapper.reconfigure()`

```python
if hasattr(sys.stdout, 'reconfigure'):    # ✘ 3.6 上是 False
    sys.stdout.reconfigure(encoding='utf-8')
```

Ubuntu 18.04 自带 Python 3.6，这个方法 **3.7 才有**，
于是设置被**静默跳过**，之后打印中文就崩。

→ 用 `codecs.getwriter`（2.6+ 都有）。

### 2. Python 2 的 `sys.stdout` 没有 `.buffer`

```python
buf = getattr(stream, 'buffer', None)     # ✘ Python 2 上是 None
if buf is not None:
    return codecs.getwriter('utf-8')(buf)
```

ROS Melodic 的节点跑在 **Python 2.7** 下，同样静默跳过。

### 3. `codecs.StreamWriter` 不接受字节串

修好前两条后，用 `getwriter` 包 Python 2 的 `sys.stdout`，会引入新问题：
`traceback.print_exc()` 往流里写**字节串**，标准 `StreamWriter` 收到后
会先 `decode('ascii')`，遇到非 ASCII 就崩：

```
UnicodeDecodeError: 'ascii' codec can't decode byte 0xe5
```

后果是**为了看清异常而打印异常时崩掉**。必须自定义 writer，
字节串原样写、unicode 编码后写。

### 4. `rospy.loginfo()` 打中文直接崩（本项目最严重的一个）

`rosgraph/roslogging.py:249` 里：

```python
msg = msg.replace('${message}', str(record_message))
```

Python 2 的 `str(unicode)` 用 **ASCII** 编码，于是**任何节点**
只要 `rospy.loginfo(u'中文')` 就崩。

→ 在 record 进 handler **之前** patch `logging.Logger.makeRecord`
（见各节点的 `fix_ros_logging`）。

### 5. `u'...%s' % exc` 在 Python 2 下会崩

实测（Python 2.7.17）：

| 异常消息 | 结果 |
|---|---|
| ASCII | OK |
| unicode | OK |
| **字节串中文** | **UnicodeDecodeError** |

底层库（pyserial / 讯飞 / tf）的异常消息常是 UTF-8 字节串。
最恶劣的是它**崩在异常处理路径上**，真正的错误信息再也看不到。

→ 用 `repr(exc)`（ASCII 安全）。

### 6. `roslaunch --dry-run` 是 ROS 2 的

ROS 1 里等价的用法是 **`roslaunch --nodes`** ——
完整解析（含所有 `$(find ...)` 求值）但不启动节点。

### 7. `$(eval find('x'))` 挡不住 `$(find x)` 的求值

```xml
<group if="$(eval find('base_control') is not None)">
  <include file="$(find base_control)/launch/stm32.launch" />   <!-- 仍会抛异常 -->
</group>
```

roslaunch 会**先求值子元素的 `$(find)`，再判断条件**。
所以"包不存在时优雅降级"在 ROS 1 里做不到。

→ 用 `scripts/make_stub_packages.py` 为缺失的包生成桩包，让
`rospack find` 成功。

### 8. `move_base` 的 `latch_xy_goal_tolerance` 必须在顶层

它属于 `/move_base/`，不是 `/move_base/DWAPlannerROS/`。
YAML 里写错段落会**静默失效**。

### 9. 地图 PGM 的行序要翻转

PGM 是**从上到下**存行，而 ROS 地图的 `origin` 在**左下角**。
生成 PGM 时忘了翻转会导致地图整体镜像。
