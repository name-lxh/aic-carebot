## 一、先看他们怎么做（事实）

### 1.1 语音交互

| 环节 | 他们的做法 |
|---|---|
| 唤醒 | 唤醒词“哈哈”（自己的唤醒引擎，`jie_voice/start_wake.sh`），应答后 **20 秒内**发命令 |
| 会话 | **滑动窗口**：每条有效命令把 20 秒**续期**，不是固定轮次；说“结束语音交互”主动结束，20 秒静默也结束 |
| 播报 | **离线 WAV 缓存**（`voice_core.py`：60+ 条固定短语，按文本 MD5 取文件），完全不依赖在线 TTS |
| 静止守卫 | 语音期间监测 `/odom` 速度与 TF：位移 >8 cm、朝向 >0.18 rad、速度 >0.04 m/s 即中止 |
| 结束条件 | 退出码 20 = 正常结束（说了结束语或静默 20 s）→ 进入跌倒检测 |

### 1.2 跌倒检测

| 环节 | 他们的做法 |
|---|---|
| 模型 | **YOLOv5**（`best.pt`，14 MB，SHA256 校验），类别 `fall` / `no fall`，置信度阈值 **0.50**，NMS 0.45，输入 640 |
| 运行方式 | Python3 子进程（`~/anaconda3/envs/yolo`，torch 1.10.1）+ **JPEG 管道 IPC**，不碰 ROS/底盘/音频 |
| 输入 | 现有 `/camera/rgb/image_raw`，不另起相机（没发布者时才 `start_rgb_camera.sh`） |
| 判据 | 单人、score ≥0.5、相邻帧中心位移 ≤0.30（同一人）、`fall` 连续 **≥1.0 s** 才确认 |
| 观测窗口 | 最多 **15 s**，确认即结束 |
| 实测 | `state/last_fall.json`：`frames: 4, status: confirmed`（p1 位置、朝向 p2，4 帧就确认）|

### 1.3 他们的动线与我们的对应关系

```
他们：巡视完 → p2 → p1（客厅入口，离起点约 1 m）→ 原地转向 p2（正对客厅）
      → 语音问答 → 跌倒检测（当前版本被 [MISSION_FALL_DISABLED] 关掉）→ 检查回程通路 → 回起点
我们：巡视完 → ⑦b 语音 →（新增 ⑦c 跌倒检测）→ ⑧ 回起点
```

他们的 `p1 = (0.651, 0.004)`、`p2 = (0.781, -1.567)`；**p1 距起点约 0.65 m**，
而我们的 `living_in = (0.42, -0.90)` 距起点 **0.99 m**——正好是你要的“离起点 1 m 的入口处”。

## 二、跌倒检测方案（新增 ⑦c）

### 2.1 位置与朝向

| 项 | 取值 | 理由 |
|---|---|---|
| 检测点 | `living_in (0.42, -0.90)` | 离起点 0.99 m，是回程必经的入口 |
| 朝向 | 面向 **(0.78, −1.57)**（他们 p1→p2 的方向），yaw ≈ **−62°** | 正对客厅对面的墙，且是他们实测确认过跌倒的视角 |
| 停车精度 | 到点误差 ≤0.30 m（现有容差）| 跌倒检测对位置不敏感，朝向更重要 |

### 2.2 流程（⑦c，插在语音之后、回起点之前）

```
⑦b 语音结束
  │
  ├─ 1. 导航到 fall_point（living_in）
  ├─ 2. 原地转向目标 yaw（move_base 同点重发，yaw 容差 0.12 rad；失败兜底：cmd_vel 慢转到 ±3°）
  ├─ 3. 等 1.0 s（曝光稳定）→ 起 worker（conda yolo + factory_fall_worker.py，30 s 内 ready）
  │      失败 → 播报"跌倒检测未启动"，直接进入 ⑧（不判任务失败）
  ├─ 4. 观测循环（最多 15 s，2~3 Hz）：
  │      抓 /camera/rgb/image_raw 最新帧 → JPEG → worker → people
  │      evidence.update(now, people)：单人 + score≥0.5 + 中心位移≤0.30 + fall 连续 ≥1.0 s
  │      → FALL_CONFIRMED 立即停
  ├─ 5. 播报：
  │      确认   → "检测到疑似跌倒，请及时处理"（可选加一句"演示模式，正在模拟拨打一二零"）
  │      未确认 → "未检测到跌倒，环境正常"
  └─ 6. 关 worker、停相机（若后面不再用）→ ⑧ 回起点
```

### 2.3 相机从哪来（关键冲突）

我们现有的 ⑦a 为了给 ASR 让路会**杀掉相机**，而跌倒检测要用相机。两种处理：

| 方案 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **A（推荐）** | ⑦a 不再杀相机，语音和跌倒检测共用 | 0 | 需实测“相机开着时 ASR VAD 是否正常”（pulseaudio 已解决，理论上没问题）|
| B | ⑦c 里重新起 astra（`roslaunch astra_launch astra.launch`），等就绪再检测 | +10~15 s | 重新枚举 USB，曝光要重爬；相机可能抢占失败 |

## 三、语音逻辑改造方案（参考他们的会话模型）

### 3.1 现在的问题

我们的 5 轮模型每轮都要“先喊老张同学 → 15 s 内说指令”，实测反复卡在同一处：
**喊了唤醒词、车回了“我在”，随后 15 s 内没有指令**（两轮全流程都断在这里）。

### 3.2 改成他们的“会话 + 滑动窗口”

```
第 1 轮：车主动问（不用唤醒）
   ↓ 听到任意有效指令 → 执行 → 窗口续期
唤醒后进入会话（他们 20 s，我们先用 20 s）：
   每一条有效指令都让窗口重新计时；
   说"没什么事" → 结束语音交互 → 进入 ⑦c 跌倒检测
   静默 20 s → 同样结束
   总时长上限 180 s（防卡死）
```

要点：
1. **唤醒一次即可**，不再每轮喊（消除“喊了唤醒没来得及说”的断点）；
2. 每条指令续期 20 s，用户思考时间更宽松；
3. 保留“没什么事”作为结束语；“导航到 X”这类长动作执行完继续会话；
4. 语音阶段加**静止守卫**（照他们的思路）：对话期间位移 >8 cm / 朝向 >0.18 rad / 速度异常 → 中止对话、直接进入跌倒检测，避免“说着话车在动”。

### 3.3 播报可靠性：加一层本地缓存

他们用离线 WAV 缓存彻底绕开网络。我们保留在线 TTS（音质好），但**给固定播报加缓存**：

- 首次播报时把合成的 wav 存到 `~/.cache/aic_tts/<md5>.wav`；
- 之后同一句话直接放缓存（网络抖动/百度限流时不受影响）；
- 缓存缺失且网络失败 → 回落本地 espeak。

涉及约 25 条固定短语（任务播报 + 房间 + 跌倒），预生成一次即可。

### 3.4 与现有规则的差异（需要你确认）

| 项 | 现在 | 改成 |
|---|---|---|
| 轮次 | 固定 5 轮 | 不限轮次，滑动 20 s 窗口，上限 180 s |
| 唤醒 | 第 2 轮起**每轮**都要喊 | **只喊一次**（会话内不再要求）|
| 结束 | 满 5 轮 / 说“没什么事” / 静默 15 s | 说“没什么事” / 静默 20 s / 超 180 s |

> 如果你要保留“每轮都喊老张同学”，也可以做成配置项 `VOICE_REQUIRE_WAKE_EACH_ROUND`，默认关。

## 五、验收与风险

**验收**
1. 语音：连续说 5 条以上指令不中断；静默 20 s 自动结束；说“没什么事”立即结束。
2. 跌倒：人躺/蹲在客厅对面墙前，**15 s 内**播报“检测到疑似跌倒”；无人时 15 s 后播报“未检测到跌倒”。
3. 全程零失败，跌倒段不额外卡死超过 1 分钟。

**风险与兜底**

| 风险 | 兜底 |
|---|---|
| 相机被 ⑦a 杀掉、跌倒阶段没图 | 采用方案 A（不杀相机）；否则 ⑦c 里重启 astra |
| YOLO 模型加载慢/失败 | 30 s 超时 → 播报“跌倒检测未启动”，继续回起点 |
| 光照差、只拍到半个身子 | 他们实测 4 帧就能确认；我们沿用 score≥0.5 + 连续 1 s，另加“人体框面积 ≥ 画面 3%”过滤远处误检 |
| 检测期间有人走动 | 中心位移 >0.30 判为换人，证据清零重来 |
| 语音会话话太多导致超时 | 总时长上限 180 s，到点播报“时间到”并进入跌倒检测 |

## 六、离线语音（车上没有在线 TTS）· 方案

### 6.1 现状盘点

| 可用件 | 状态 | 结论 |
|---|---|---|
| 在线 TTS（百度 gettts + mpv）| 现在能用，但现场没网就废 | **不能作为比赛方案** |
| 既有离线缓存 | 92 条 WAV / 7.4 MB（按文本 MD5 命名）| 架构可用，但句子集与本项目不同：34 条静态播报里只命中 3 条 |
| 讯飞离线 TTS（`xf_tts_cli`）| 源码在、二进制没编过；此前记录是“坏了” | 不作为主方案 |
| `espeak`（系统自带）| 能出声，但缺中文词典，含糊 | 只做最后兜底 |

结论：**把固定播报全部预先做成 WAV，运行时只查表播放，不合成、不联网**。

### 6.2 运行结构

```
任务代码 say(u'卧室电灯已打开，窗帘已拉开')
        │
        ▼
 /voice/say（std_msgs/String）
        │
        ▼
 tts_play.py（替换 tts_net.py）
        │  ① 整句精确匹配 → cache/<md5(文本)>.wav → aplay（毫秒级，零网络）
        │  ② 带数字的句子 → 拆成"前缀 + 数字 + 单位"逐段播（数字用 0~9/十/百/千/点 的缓存片段）
        │  ③ 缓存缺失 → espeak 兜底 + 日志告警（提示补录）
        ▼
 PCH 声卡（ALSA 直连，音量 70%~86%）
```

### 6.3 缓存怎么来（关键：趁现在有网一次做完）

1. **清点语句**：`check_coverage.py` 已把 m36 + voice_dialog 里的静态播报抽出来（当前 34 条）。
2. **补全清单**：再加上跌倒检测、语音会话、异常兜底的句子，凑成约 45 条。
3. **批量生成**：`build_voice_cache.py`
   - 有网时用在线 TTS 一次生成全部 WAV（16 kHz/单声道/16 bit，统一音量归一化）；
   - 每条校验时长与峰值，失败的单独重试；
   - 写入 `manifest.json`（文本 → 文件名、时长、生成时间、来源）。
4. **数字片段**：`零 一 … 九 十 百 千 点 负` 各一条，配合前缀/单位拼动态句。
5. **人工替换**：对特别重要的 5~8 句（问候、核验通过、跌倒告警），可用手机录一版人声替换。

### 6.4 动态句子的处理

| 句子 | 拆法 |
|---|---|
| 当前室内温度 21.5 摄氏度 | `当前室内温度` + 数字片段 + `摄氏度` |
| 光照强度 54.0 勒克斯 | `光照强度` + 数字片段 + `勒克斯` |
| 您当前的心率是 74 次每分 | `您当前的心率是` + 数字片段 + `次每分` |
| 厨房烟雾浓度 0 | `厨房烟雾浓度` + 数字片段 |

### 6.5 验收

- 断网拔网线跑一轮：全部播报正常、无静音、无 espeak 兜底告警；
- 单句播报延迟 <300 ms（本地查表 + aplay）；
- 缓存命中率 100%（日志里不出现 missing）。

## 七、一次唤醒的会话模型（详解）

### 7.1 状态机

```
            ┌──────────────────────────── 车主动提问（第 1 轮，不用唤醒）
            ▼
   ┌──► LISTEN_15 ──有效指令──► EXEC ──动作完成──┐
   │        │                                    │
   │        │静默 15 s                           │
   │        ▼                                    │
   │      BYE ──► ⑦c 跌倒检测                    │
   │                                             │
   └──────────── SESSION_20 ◄────────────────────┘
            │      ▲ 每条有效指令 → 窗口重置为 20 s
            │      │
            │      └── 听到"老张同学" → 回"我在" → 窗口重置（不占轮次、不扣时间）
            │
            ├── 听到"没什么事" ──► BYE ──► ⑦c
            ├── 静默 20 s ──────► BYE ──► ⑦c
            └── 总时长 > 180 s ─► BYE ──► ⑦c
```

### 7.2 与现在 5 轮模型的差别

| 维度 | 5 轮模型（现在）| 会话模型（改成）|
|---|---|---|
| 唤醒 | 第 2~5 轮**每轮**都要喊 | **只喊一次**；之后任何时候喊都只是“刷新窗口”|
| 窗口 | 固定 15 s / 轮，错过就丢一轮 | 每条指令**续期 20 s**，说多长都行（上限 180 s）|
| 轮数 | 固定 5 轮 | 不限（受 180 s 与“没什么事”约束）|
| 断点 | 喊了唤醒、15 s 没指令 → 整段结束（**两轮实车都断在这**）| 喊了唤醒还有 20 s；说完指令又续 20 s |
| 长动作 | 导航完回到下一轮 | 导航执行完**自动回到会话**，不用重新唤醒 |

### 7.3 时序细节（每条都要落到代码里）

| 事件 | 动作 | 计时 |
|---|---|---|
| 会话开始（第 1 轮）| 播“主人，有什么我能帮你的” | 播完 +1.0 s 再开麦 |
| 听到唤醒词 | 回“我在” | ACK 后 0.4 s 清回声 |
| 听到有效指令 | 执行；执行完播报结果 | 播报结束后**重置** 20 s 窗口 |
| 听到听不懂的话 | 播“没听清，请再说一次” | 窗口**不重置**（避免噪声刷时间）|
| 静默 | — | 20 s 到点播“那我先忙了” |
| 说“没什么事” | 播“好的，我随时都在” | 立即进入 ⑦c |
| 长动作（导航）| 动作期间不计时 | 动作完成播报后重置窗口 |
| 静止守卫触发 | 播“那我先忙了” | 立即进入 ⑦c |
| 总时长超限 | 播“时间到，我先去忙了” | 立即进入 ⑦c |

### 7.4 三个必须处理的边界

1. **回声**：说法“我在/好的”由车播报，麦克风会同时收音。沿用现在的做法——播报后按字数估时 + 清空识别缓冲（`_say` 里的 `extra`）。
2. **噪声误触发**：辨识置信度阈值 5（V100 值），噪声一般 0~4 分；再加“窗口不因听不懂而续期”，避免噪声把会话无限延长。
3. **会话期间车不能被推动**：加静止守卫（位移 >8 cm / 朝向 >0.18 rad / 速度 >0.04 m/s → 立即结束会话进入跌倒检测）。

### 7.5 需要的配置项

```python
VOICE_SESSION = True          # True=会话模型；False=回到 5 轮模型（保留旧逻辑，随时可退）
WINDOW_FIRST = 15.0           # 第 1 轮静默窗口
WINDOW_SESSION = 20.0         # 会话内每条指令后的窗口
SESSION_MAX = 180.0           # 会话总时长上限
WAKE_ACK = u'我在'
EXIT_PHRASE = u'没什么事'
```

### 7.6 验收标准

1. 连续说 6 条以上指令不中断（含 1 次导航），每条都命中；
2. 说完“没什么事”1 秒内进入跌倒检测；
3. 不说话时 20 秒后自动结束，进入跌倒检测；
4. 会话期间车被推动 → 立即结束会话、进入跌倒检测，不继续执行语音指令。
