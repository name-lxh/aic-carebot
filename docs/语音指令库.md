## 一、唤醒与会话规则

| 规则 | 内容 |
|---|---|
| 唤醒词 | **老张同学**（回“我在”，不占轮次、不扣时间） |

## 三、识别容错规则（判定的细节）

| 规则 | 值 | 说明 |
|---|---|---|
| 意图匹配阈值 | **0.80** | 识别文本与标准说法相似度 ≥0.80 才算命中 |
| 必含关键字 | 灯 / 风扇 / 窗帘 / 热 | 防止“打开”+乱码被判成设备指令 |
| 数字/单位 | 不参与匹配 | 温度值由系统读传感器，用户不用报数 |
| 允许的偏差 | 少一个字可过 | 例：“查询室内温”（0.91）能命中 |
| 必须拒绝的输入 | 厨房、到厨房、带我去厨房、打开O、关闭P、小车P、我有点执 | 以上都**不能**被当成指令（已在自测里锁定）|

## 五、要加指令时需要动三处

1. `vocab/call.bnf`：加一行 `<新槽>:说法;` 并挂到 `<callstart>`；
2. `intent_match.py` 的 `VOCAB`：加 `('意图名', [u'说法'])`（`REQUIRED` 里按需加关键字）；
3. 任务代码：给这个意图写执行分支（`voice_dialog.py` 的 `_do_intent`）。
4. 若走离线播报，把新回复句加进 `_tools/voicecache/phrases.txt` 并重跑 `build_voice_cache.py`。

> 讯飞 BNF 每次改动都要重装文法并重启 ASR（约 22 s），这也是它“不好用”的原因之一。

## 六、关于“不用讯飞”

讯飞这套的实际问题（今晚实测）：

- 噪声下会凑出 0~7 分的短语，需要把置信度阈值卡在 5，稍微远一点真指令又只有 8~11 分，**窗口很窄**；
- 封闭 BNF + 每次改文法要重装重启，调试成本高；
- 必须独占麦克风，和相机/其他组抢设备时容易 VAD=0。

替代方案（车上已有现成条件）：

| 方案 | 条件 | 优点 | 代价 |
|---|---|---|---|
| **Vosk 离线识别** | `/home/ub/talos_venv` + `vosk-model-small-cn-0.22`（66 MB，已装）| 离线、CPU、支持**语法受限识别**（把 14 条指令写成 grammar，识别率显著提高）、不需要 pulse | 起一个 py3 子进程，多占约 200 MB 内存 |
| 在线 ASR（百度/腾讯）| 现场有网 | 识别最准 | 断网即失效，延迟 1~2 s |
| PocketSphinx | 系统自带包 | 极轻 | 中文效果差，不建议 |

建议：**换 Vosk + 语法受限**。对上层完全透明——它只要往 `/voice_words` 发识别文本，`voice_dialog.py` / 意图匹配 / 播报都不用改。
